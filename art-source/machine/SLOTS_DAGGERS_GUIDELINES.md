# ShakeHero：Slots & Daggers 美术与渲染准则

日期：2026-10-14。参考版本：本机 Slots & Daggers 1.0.20，Unity 6000.2.6f2。

> 最新用户要求：约1源像素黑描边、1–2源像素金属边，多种底板材质，面板/按钮高低错落且互相遮挡，边缘不完全对齐。结构必须从头重做，不能继续厚机壳换色。完整探索稿见 [fullscreen-v5-layered](concepts/fullscreen-v5-layered/README.md)。以下技术证据保留；第5节局部样板流程已结束且被否定，不能当作当前推进计划。

> 用户纠正（2026-10-14）：金色磨损并非参考机台的材质规律。此前“旧黄铜/做旧/露底”的设定是助手的错误推断，撤销。以用户最新局部参考为准：灰绿底、近黑边、灰白或灰绿短亮边；黄褐文字独立于机壳。技术逆向结论不变，不能用它为错误的材质判断背书。

**结论：以小尺寸像素零件组装机台，让独立贴片在三维空间中形成薄层叠压，再用灯光、阴影和后处理统一画面。** 原作同时使用少量真实模型。我们的目标是让玩家先读到像素造型、薄板关系和功能，再感受到空间与光照。

本准则用于下一轮原创样板和后续实现。它替代此前仅凭截图得出的技术假设，不代表已改动运行游戏，也不取消 402×874 和既定页面功能。v10 方向稿继续废弃；上一轮 A/B/C 仅留作密度试验，不作为造型基准。

## 1. 已核实的原作做法

证据来自用户指定的安装包：`C:\Program Files (x86)\Steam\steamapps\common\Slots and Daggers`。读取了场景、资源、材质和少量相关程序集类型。安装包不是原始 Unity 工程；下面参数是序列化配置，运行时设置可能改变。数量包含未激活对象、重复符号和备用界面，不等于某一帧的绘制次数。

| 观察 | 本地证据 | 对我们的启示 |
|---|---|---|
| 机台主要由独立 Sprite 组装 | `level0` 的 `LEVEL/MACHINE PARTS` 层级：961 个 SpriteRenderer、77 个 MeshRenderer；整个场景为 1341 / 156 | 主体资产应拆成面、边框、装饰、按钮、螺钉。MeshRenderer 数量不能直接当成实体模型数量，其中包含光效、遮罩、辅助遮影几何 |
| 常用零件非常小 | Frame A 32×36；Frame B 29×37；Surface A 28×28；Screw A 4×4；Play Button A 17×18 像素 | 先把小图形画成立，再放进场景；避免生成一张带完整材质和摄影光照的大机台图 |
| 单件颜色很少 | Frame A/B 的非透明像素各只有 5 色；Surface A 只有 3 色；花边 Frame C 是白色遮罩 | 用离散色块、短亮边、深色轮廓塑形。材质变化可由染色和光照补充 |
| 支持复用和拉伸 | 这些 Sprite 具有切片边界；Health Display 外框 drawMode=1、面板/花边=2，对应 Sliced/Tiled | 九宫格保持角部像素尺度；直边延长或平铺，不能把整张小图随意拉扁 |
| 贴片确实有层间深度 | 同一 Health Display 父节点下：面板 local Z≈0.030、花边≈0.024、螺钉≈0.0178、外框≈−0.020 | 视觉层与零件一一对应，层间距离服务于遮挡和投影。不是把同一轮廓复制几十层来堆出体素实体 |
| 像素贴图参与 3D 光照 | 大量 Sprite 使用 `Shader Graphs/Sprite With Depth`；Shader 元数据为 URP Lit，有 ShadowCaster、DepthOnly、DepthNormals Pass；选取的面板、外框、螺钉启用投影/接影 | Sprite 不必全部 Unlit。可保留真实灯光和阴影，同时保持像素轮廓 |
| 基础材质低光泽，局部可有变化 | 基础 Sprite With Depth 的 Metallic=0、Smoothness=0；Smooth Less / Smooth 变体分别为 0.4 / 0.5 | 基础机壳保持哑光；有理由的玻璃或局部材质可有高光，不能给整台机身统一套亮金属 |
| 相机是透视 | Main Camera 和 Cinemachine 镜头 FOV=38°；Main Camera orthographic=false | 可保留轻微透视和镜头运动。不能把“必须正交”写成原作规律 |
| 清晰像素与柔和光效共存 | 主 Sprite Atlas 1024×1024、Point 采样；Light Cookie、部分前景纹理采用 Bilinear；全局 Volume 引用 Bloom 和景深配置，相机开启后处理 | 结构纹理用最近邻；光晕、光罩、远近氛围可平滑。不能把全画面都强制硬边 |
| 并非整帧固定低分辨率渲染 | 高画质 RP RenderScale=1；中/低为0.7；MSAA=1，相机后处理 AA=0 | 像素风首先来自资产。无需为了“像素”降低中文文字和所有 UI 的分辨率 |
| 保留少量真实模型 | 资源中有 Slot Wheel 01、Coin A、Ashtray A、Glass A、Dice A 等网格 | 滚动、翻转或需要改变轮廓的道具可以用低面数模型；静态边框通常不必建厚实体 |

样本原色（未受场景光照、染色、后处理影响）：Frame A 为 `#161715 #434D3A #5D6555 #6B7561 #9BA591`。这是测量结果，不是最终截图配色，也不是要求本项目原样照抄。

证据图：[原始 Sprite 小样](research/slots-daggers-1.0.20/sprite-evidence.png)。机器可查记录：[facts.json](research/slots-daggers-1.0.20/facts.json)，含安装文件哈希、对象 ID、样本颜色、层级与设置。

### 证据边界

- `Sprite With Depth` 的名称与 Pass 支持深度参与，但未恢复原始 Shader Graph 节点，不能据此宣称它使用高度图、逐像素挤出或特殊法线生成算法。
- 没有进行运行时 GPU 抓帧；不能把资源数量当成性能预算，或把序列化值当成所有状态下的最终值。
- Bloom 基础强度为3、阈值约0.65，且设置代码会随屏幕高度调整；这些是 Unity 渲染链参数，不能直接复制到 UrhoX。
- 原作主灯序列化为硬阴影，画质配置未开启软阴影支持；后处理仍会影响最终观感。“原作一定依靠软阴影”不成立。
- 发现了 ParallaxObject、SnapPositionToGrid 等代码类型，但本次选取的场景中未核实其挂载实例，不把类型存在当成正在使用的证据。

## 2. 我们当前为何仍像 3D 模型

现有实现已经包含贴片，但粒度偏大：`BodySprite.lua` 主要是整机底色与整机墨线两张面，主体后壳和许多控件仍由 `Cabinet.lua` 加载实体几何。贴图主要覆盖实体的表面，模块之间缺少原作那种独立薄片关系。

`Projection.lua` 采用30°倾角；它与实体回口、连续边框明暗一起，强化了“俯看厚机台”的读法。`MachineMetal.shader` 已降低高光，因此继续只降金属度或减少锈迹，收益有限。上一轮 A/B/C 固定了原框体几何，只改变磨损密度，三档自然保留同一种体积感。

`Screen.lua` 的672×896双线性内容纹理、连续曲率与扫描线，会让屏幕细腻程度和外框像素尺度形成另一套节奏。应分别管理屏内图形、文字、玻璃效果的采样与清晰度，不能简单把整个屏幕都改成低分辨率。

## 3. 原创资产准则

以下数值是 **ShakeHero 的首轮试验参数**，不是原作参数。

| 项目 | 制作准则 | 验收方式 |
|---|---|---|
| 像素尺度 | 以402×874交付画面为基准。机台结构首选1源像素≈2画面像素；即正面静态排版可用201×437结构网格。透视后会有局部偏差，不宣称全屏逐像素精确对齐 | 同类螺钉、边角、线宽看起来属于同一套资产；禁止高分辨率噪点混入低分辨率边框 |
| 文字 | 中文、说明、数字保持独立清晰渲染；不纳入201×437整体降采样，不把动态文字烘进底图 | 在402×874原尺寸直接阅读，无须放大 |
| 基础零件 | 原创边框母版约24–40源像素；面板约16–32；螺钉3–5；主图标12–24。长边用切片/平铺扩展 | 母版原尺寸能读懂形状，放大后仍是有组织的色块 |
| 调色板 | 同一基础材质先用3–5档明暗，加1个必要的功能色；维持深灰绿主体、暗缝、灰绿亮边，暖色集中在光源与焦点 | 关闭氛围光后也有清楚造型；不靠数百色连续渐变画倒角 |
| 轮廓与边缘 | 以1源像素暗边、局部1源像素亮边为起点；接缝必要时加到2源像素。切角、断续亮边、边缘缺口优先 | 连续厚金边、整圈等亮倒角、圆润高光不得成为主轮廓 |
| 表面细节 | 板面以低对比同色系像素变化和少量几何装饰为主，至少85%保持安静；不默认加入划痕、掉漆、露底或锈迹 | 结构靠轮廓和叠压成立；不得出现散布的金色斑点或掉漆纹理 |
| 零件拆分 | 面板、边框、花边、螺钉、按钮面、灯芯、玻璃各自独立；局部阴影可单独控制 | 可以单独隐藏、换色、调整层距，不能靠一张大图同时决定材质、阴影和布局 |
| 变化方式 | 用复用、染色、灯态、少量局部版本形成变化；非必要不为每块面板重新生图 | 同材质相邻部件不出现不同颗粒、不同光向、不同线宽 |

完整机台彩图仅适合探索气氛。生产资产应输出透明底、正面视角、无文字的零件，统一像素网格后人工修边。生图即使写了 pixel art，也要检查是否只是给平滑模型覆盖了碎点。

## 4. 层叠、材质和灯光准则

- **不同底板必须可辨。** 最新参考同时包含棕色横纹、灰绿细点和深绿菱形纹。材质分区通过纹理组织与色阶区分，不能把全屏统一刷成灰绿金属，更不能用金色磨损代替材质差异。
- **独立面板必须形成遮挡。** 先画前后关系：标签部分藏在前板后；计时牌跨过屏幕/底板接缝；按钮边缘越过底板。上下左右偏移服务于层次，功能文字保持完整。浅层投影和布局错位分别控制，不能把布局错位理解成厚侧壁。

屏幕角局部建议拆成如下独立层，最终遮挡关系以正面视觉验证：

```text
靠近相机
  螺钉 / 指示灯芯 / 按钮面（按实际位置分别摆放）
  窄像素边框
  花边与刻印
  屏幕玻璃 / 屏内内容（位于边框开口内）
  平面基板与开口暗底
  支撑体 / 桌面
远离相机
```

- **厚度首先用遮挡表达。** 不透明零件采用透明裁切的像素轮廓；为必要部件分配真实层距，使其投影到下一层。基础材质允许接光，粗糙、低镜面反射。
- **先定像素尺度，再定层距。** 样板中相邻板层投影错位以1–3个画面像素为起点，最多选一处加强。层距由投影结果调整，不照搬原作0.03等世界坐标。
- **3D保留在有收益的地方。** 桌面承接阴影、按钮按压、可翻转道具和少量支撑体可以保留；屏幕边框、装饰、固定螺钉先尝试 Sprite。无需重写整个引擎渲染方案。
- **受光和画出来的明暗要分工。** 贴图负责轮廓、短亮边和同色系表面变化；灯光负责场景方向、照度变化和层间投影。不把受光解释成金色材质，不默认绘制磨损。
- **只保留一个清楚的主光方向。** 主体保持灰绿与中性边缘；灯光色按具体参考场景调整，不默认全局琥珀罩染。灯芯与文字可用独立功能色，白色遮罩可染色复用。
- **结构清晰，氛围柔和。** 像素资产最近邻；灯光罩、Bloom、环境雾允许线性采样。后处理不得吞掉细边、冲淡暗缝或模糊关键中文。
- **透视以模块易读为限。** 首轮试验先把机台画得更接近正视，检查厚侧壁是否仍抢眼；可测试0–10°倾角，但这是本项目建议，不是推断原作角度。相机调整必须同步点击映射。
- **动作保持分层。** 按钮面小幅位移、灯芯独立亮灭、面板轻震即可形成触感；运动后落点稳定，不让边缘持续半像素闪烁。

## 5. 历史屏幕角样板制作合同（已结束，不再沿用）

先重做同一处屏幕角的结构主样，再比较密度。禁止继续把上一轮厚框当固定几何。

1. 选择约104×84源像素的局部工作区，以2倍显示为208×168画面像素；在402×874全图原位置放回，必要时裁边，不把整张画面拉伸。
2. 原创制作6–8个可分离资产：底板、开口暗底、窄边框、装饰条、螺钉、灯座/灯芯、玻璃；现有玩法内容与文字单独保留。
3. 先交付无氛围光、无Bloom的平光版，确认像素尺度、切角、薄层关系。再添加主光、投影、局部发光，保留两版用于对照。
4. 在同一结构主样上出三档：A低密度≥95%安静板面；B中密度≥85%；C高密度≥75%。只调整装饰覆盖，固定零件尺寸、轮廓、层距、颜色档数与主光。
5. 同时交付402×874原尺寸、局部最近邻4倍图、逐层拆解图。图中注明静态概念拼接或实际运行截图，不混用证据。
6. 先按下列硬性条件验收，再决定哪档密度进入实现；B是测试起点，不是已确认最终选项。

| 硬性条件 | 通过标准 |
|---|---|
| 像素造型 | 无光版也明显是少色像素零件，亮边不依赖连续柔滑渐变 |
| 薄层关系 | 边框、板面、螺钉可单独辨认；没有大面积厚倒角或突出侧壁主导画面 |
| 一致性 | 同类零件像素尺度一致，光向一致；没有额外编造的金色磨损或均匀撒点纹理 |
| 信息优先级 | 402×874下，棋盘、数字、主要按钮先于外框被注意到；中文清晰 |
| 后处理 | 开关Bloom后结构都成立；发光不会连接成一条糊边；字与细图标无明显重影 |
| 可维护性 | 修改某个边框/灯态不需要重生整机；原创资产与引用研究材料明确分开 |

## 6. 对现有实现的改动顺序

这是一份实施顺序，当前尚未执行：

1. `scripts/Machine/BodySprite.lua`：把整机两层图逐步拆成局部可控零件；首先只处理屏幕角，验证成本。
2. `scripts/Machine/Cabinet.lua` 与网格数据：在样板通过后弱化该区域厚框/回口，保留需要的承影与动态几何，避免贴片和旧实体同时出轮廓。
3. `scripts/Machine/Projection.lua`：独立比较倾角与层距，点击、绘制和相机变换共同验证，不先全局改镜头。
4. `assets/Shaders/BLGL/MachineBodySprite.shader`：评估像素裁切、接光/接影与深度写入的明确分工；不能只按 Shader 名称仿写未知算法。
5. `scripts/Machine/Screen.lua`：保留动态内容与交互，分别评估图形采样、文字清晰度、玻璃曲率和Bloom。该项不等于把672×896粗暴降成201×437。

生产资源必须原创。研究用小样仅放在 `art-source/machine/research/`，不接入 `assets/` 或运行时；本次没有改动 Steam 安装目录、玩法代码或运行配置。
